# 对话记录与导出：阶段 0 可行性记录

基线：LunaTOC `212262b60b6e37466e571b61ef7500d6a58d1337`，所附 Black Box 的内部 `VERSION = '57'`。本阶段不启用持续记录，也不提供正式导出。

## 已验证

- LunaTOC 已有主世界的同源会话读取、分页、按父节点确认有效分支的机制。完整分页和无法证明完整时返回空结果的单元测试通过。现有目录模型仅保留导航所需的文本，不能直接作为 DOCX 的格式化正文。
- 模拟分页并在两次请求间修改旧消息时，现有刷新仍将两个版本的消息标记为已验证分支。新增测试明确重现这一风险。该机制可辅助确定分支，不能充当点击时刻的原子内容快照。
- Black Box v57 的页面遍历会写入 IndexedDB；用户消息的原生复制需要拦截页面剪贴板；图片跨域回退依赖油猴接口；DOCX 生成按每次图片引用重复写入媒体文件，且只渲染一部分 Markdown 格式。以上功能均不能直接移植为正式导出。
- 增加一次性兼容性检查按钮，位于侧边栏标题与搜索按钮之间。点击时复用现有只读会话刷新，检查当前已挂载的页面标记，并尝试读取当前可见的一张图片。扩展生成本地文字报告，不记录正文、图片数据、账号标识或会话地址。检查结果只代表当前对话和当前页面状态。
- `npm run typecheck`、`npm test`、`npm run build` 已通过。本地执行环境缺少可运行的 Chromium；仓库的 [浏览器检查](https://github.com/PyRookie1/LunaTOC/actions/runs/45825833680) 已在隔离 Chromium 中通过，共 23 项浏览器检查、887 项单元测试，并完成扩展构建和依赖审计。此结果验证模拟页面与扩展构建，不代表真实 ChatGPT 页面。
- 2026 年 11 月 26 日的已登录页面报告：现有只读刷新确认当前有效分支含 324 个节点，其中用户消息 103 条；会话数据含 1 处图片内容和 1 个附件；当前显示区域的一张图片可读取，返回 689306 字节。该页面当前已挂载的节点未提供 `[data-message-id]`；仅发现 7 个复制控件和 7 个展开控件。固定范围不能依赖当前 DOM 的消息 ID；应以会话数据中的消息身份为主，再验证格式与图片对应关系。此报告未采集正文，无法证明长消息正文是否完整，也无法证明所有图片可读。

## 仍未验证及阶段门槛

1. **真实页面契约**：已在一段长对话中确认有效分支读取和当前显示图片的读取。折叠长消息的正文保真、其他历史图片及实际分支切换仍需在对应实现阶段验证，不能从数量推断为已通过。
2. **点击时刻边界**：分页没有共同版本号或服务器快照证明时，无法证明点击瞬间的完整内容。产品需选定可验证的版本机制；若不存在，则改为“扫描期间保持稳定，发生历史变动即中止”，并在最终读取前后验证固定范围。此规则须在阶段 3 开发前确定。
3. **长消息准确性**：现有页面复制方案会改写剪贴板方法并模拟点击，尚未验证安全、用户剪贴板不变和完整格式；不得在后台持续记录中使用该方案。先比较完整 API 数据与折叠、代码块等真实样本，再决定是否需要交互式回退。
4. **图片来源与权限**：实际图片来源、获取状态、格式和尺寸必须在真实页面验证。阶段 0 检查仅试取一张当前已挂载图片；它不能证明所有历史图片均可获取。
5. **DOCX 格式和下载**：现有 Black Box 实现仅是原型。应以单独的格式样本和图片去重样本验证文档；正式成功报告必须依据浏览器下载完成状态。

**当前结论：阶段 0 尚未通过。** 真实页面的分支与当前图片读取、模拟浏览器检查已通过；严格的点击瞬间快照没有可验证来源。需先明确时间边界的可实施规则，才能启动阶段 1 的正式记录开发。DOCX 及下载能力仍须在第三阶段通过样本验收，不得从本次报告推定已完成。

## 一次真实页面检查

将本分支构建目录作为已解压扩展加载。在包含长消息和至少一张可见图片的 ChatGPT 对话中，打开 LunaTOC 侧边栏，点击标题右侧的“检查当前对话兼容性”。扩展生成 `LunaTOC-兼容性检查-*.txt`；检查文件中不含私人正文后，可提供该文件用于开发方分析。若要检查历史分支，切换分支后再次点击即可。无需打开开发者工具或手动复制页面数据。

当前报告未验证 DOCX 的实际生成和保存，不应用作产品完整性证明。完成阶段 0 后应删除或隐藏此临时按钮，并将需要的统计接入正式的本地诊断流程。
