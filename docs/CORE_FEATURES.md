# LunaTOC 核心功能验收

LunaTOC 的核心能力包括对话目录、回答标题导航，以及 ChatGPT Markdown 粗体修复。本说明用于确认这些功能的正常行为，不记录开发阶段或历史问题。

## 提示词 Markdown 导入与导出

- 提示词可导出为 Markdown，也可从同一格式的 Markdown 文件导入。
- 单个导入文件最大 **5 MiB**；文件大小会在读取正文前检查，超限文件不会载入内存。
- 单次最多导入 **500 条**提示词；标题最多 **1,000 个字符**，单条内容最多 **100,000 个字符**，整个文件最多解析 **100,000 行**。
- 任一限制超出时整份导入失败，不会部分导入、静默截断或覆盖现有提示词。可将文件拆分为多个较小文件后分别导入。
- 解析器逐行扫描，不会一次性将整个文件拆成大量行数组；无效或未闭合的提示词区块不会被导入。

## 对话目录

- 根据当前 ChatGPT 会话中已识别的用户消息建立目录。
- 可通过搜索筛选目录项目；点击目录项定位到对应问题。
- 当前提问的高亮状态与消息导航保持一致。
- 在消息尚未加载或虚拟滚动的情况下，不得把其他会话的提问错误当作目标。
- 会话切换、页面重新挂载时，不应出现不同会话数据混合。

## 回答标题导航

- 只从对应助手回答中提取可见的 H1～H6 标题。
- 最多展示实际存在的前三个标题级别，并压缩为目录缩进一、二、三级。
- 跳过空标题、不可见的标题、辅助阅读器专用标题、代码块中的伪标题。
- 同一回答中同级同名标题，应以出现顺序区分。
- 点击标题应导航到当前回答中的目标标题；后续导航操作可取消前一次尚未结束的定位。

## Markdown 粗体修复

- 仅修复 ChatGPT 助手回答 Markdown 中安全、完整的 `**文本**` 标记；用真实的 `strong` 标签呈现，不解析不可信 HTML。
- 保持普通文字原有顺序，不更改 ChatGPT 消息源数据。
- 不处理提问文字、代码块、行内代码、已经正常渲染的粗体、不完整或转义的标记。
- 行内和块级数学表达式中的双星号保持原文；同一文本节点中位于数学表达式之外的合法粗体仍可修复。
- 支持回答文本持续生成和新答案动态挂载；重复观察不应产生多层重复粗体。

## 自动验收

运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`、`npm run test:browser:setup`、`npm run test:browser`。CI 还会执行 Manifest 引用检查、ZIP 完整性校验和依赖安全审计。

单元测试验证导航数据与 DOM 处理，Chromium 浏览器测试在隔离的模拟 ChatGPT 页面上加载实际扩展构建产物。模拟环境不等于真实 ChatGPT 登录页面，线上兼容性必须另外验收。
